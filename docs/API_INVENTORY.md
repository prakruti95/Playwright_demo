# API Inventory & Network Specification: Northline Store

**Target Base URL:** `https://ecomcicid.netlify.app`  
**Host Environment:** Netlify Edge (Static hosting with client-side SPA fallback)  
**API Protocol:** REST / JSON (over HTTPS)  
**Authentication Header:** `Authorization: Bearer <token>`  
**CSRF Protection:** Initialized via `/api/csrf`

---

## 1. Network Architecture & Deployment Realities

### Target Hosting Observations
When inspecting network traffic generated by `https://ecomcicid.netlify.app/`, all API routes are prefixed with `/api/`. Because the target Netlify deployment hosts a static build without active Netlify Functions for dynamic write verbs, the live server responses behave as follows:
- **`GET /api/*`**: Returns `200 OK` with `Content-Type: text/html` (Netlify's 200 SPA rewrite rule returning `index.html`).
- **`POST /api/*`**: Returns `404 Not Found` with `Content-Type: text/html` (Netlify's default 404 error page).
- **`PATCH /api/*` & `DELETE /api/*`**: Returns `405 Method Not Allowed` with `Content-Type: text/plain`.

### Client-Side Fallback & Resilience Strategy
The application incorporates a robust resilience layer (`isOfflineOrNetworkError` handler in `index-BRBlI515.js`). When an API call returns a network error, 404, or 405:
1. Catalog data falls back to `/catalog.json` (a static file returning pure JSON with categories and products).
2. Cart state transitions to a client-side Zustand store persisted in `localStorage["ecom-cart"]`.
3. Order submissions generate a local order stored in `localStorage["ecom-local-orders"]` with order prefix `ORD-LOCAL-`.
4. Authentication falls back to local credential matching in `localStorage["ecom-auth"]`.

## 2. Complete REST Endpoint Inventory

### A. Catalog & Static Endpoints

#### 1. `GET /catalog.json`
- **Method:** `GET`
- **Purpose:** Primary static catalog data source containing full product details, variants, images, categories, and inventory.
- **Request Headers:** `Accept: application/json`
- **Response Status (Live Target):** `200 OK` (`application/json`)
- **Response Payload Schema:**
```json
{
  "categories": [
    {
      "id": "cat-living",
      "name": "Living",
      "slug": "living",
      "parentId": null
    }
  ],
  "products": [
    {
      "id": "prod-linen-lounge-chair",
      "name": "Linen lounge chair",
      "slug": "linen-lounge-chair",
      "description": "A low, sculptural lounge chair in undyed linen and solid oak.",
      "price": "640.00",
      "compareAtPrice": "780.00",
      "stockQuantity": 12,
      "sku": "NL-LIV-001",
      "images": ["https://images.unsplash.com/..."],
      "categoryId": "cat-living",
      "isActive": true,
      "createdAt": "2026-09-01T10:00:00.000Z",
      "category": {
        "id": "cat-living",
        "name": "Living",
        "slug": "living"
      }
    }
  ]
}
```

#### 2. `GET /api/categories`
- **Method:** `GET`
- **Purpose:** Retrieve list of active product categories.
- **Query Parameters:** None.
- **Live Response:** `200 OK` (Static HTML fallback; client loads bundled categories).
- **Expected API Response:** `200 OK` (`application/json`) returning array of category objects.

#### 3. `GET /api/products`
- **Method:** `GET`
- **Purpose:** Query, search, filter, and paginate catalog products.
- **Supported Query Parameters:**
  - `page`: Integer (default `1`).
  - `limit`: Integer (default `12`).
  - `sort`: String (`createdAt`, `price`, `popularity`).
  - `order`: String (`asc`, `desc`).
  - `category`: Category slug string (e.g. `living`, `apparel`, `objects`).
  - `search`: Search query string (e.g. `chair`, `wool`, `ceramic`).
  - `minPrice`: Number string (e.g. `100`).
  - `maxPrice`: Number string (e.g. `500`).
  - `minRating`: Number string (`1` to `5`).
  - `includeInactive`: Boolean string (`true`/`false`).
- **Live Response:** `200 OK` (Static HTML fallback; filtered in client state).
- **Expected API Response:** `200 OK` (`application/json`):
```json
{
  "products": [...],
  "pagination": {
    "page": 1,
    "limit": 12,
    "total": 6,
    "totalPages": 1
  }
}
```

#### 4. `GET /api/products/:slug`
- **Method:** `GET`
- **Purpose:** Retrieve single product details by slug.
- **Path Parameter:** `slug` (e.g. `ceramic-pour-over-set`).
- **Live Response:** `200 OK` (Static HTML fallback; loaded from client store).
- **Expected API Response:** `200 OK` (`application/json`) with product object.

### B. Cart Endpoints

#### 5. `GET /api/cart`
- **Method:** `GET`
- **Purpose:** Retrieve current user session shopping cart.
- **Headers:** Optional Bearer token or session cookie.
- **Live Response:** `200 OK` (HTML fallback; client falls back to `localStorage["ecom-cart"]`).
- **Expected API Response:**
```json
{
  "id": "cart_123",
  "items": [],
  "itemCount": 0,
  "subtotal": "0.00"
}
```

#### 6. `POST /api/cart/items`
- **Method:** `POST`
- **Purpose:** Add item to cart.
- **Request Headers:** `Content-Type: application/json`
- **Request Payload:**
```json
{
  "productId": "prod-ceramic-pour-over-set",
  "quantity": 1
}
```
- **Live Response:** `404 Not Found` (Client captures failure and inserts line item into `localStorage["ecom-cart"]`).
- **Expected API Response:** `200 OK` / `201 Created` with updated cart object.

#### 7. `PATCH /api/cart/items/:id`
- **Method:** `PATCH`
- **Purpose:** Update item quantity in cart.
- **Path Parameter:** `id` (e.g. `temp-prod-ceramic-pour-over-set` or server item ID).
- **Request Payload:**
```json
{
  "quantity": 2
}
```
- **Live Response:** `405 Method Not Allowed` (Client catches 405 and updates item in `localStorage["ecom-cart"]`).
- **Expected API Response:** `200 OK` with updated cart object.

#### 8. `DELETE /api/cart/items/:id`
- **Method:** `DELETE`
- **Purpose:** Remove item from cart.
- **Path Parameter:** `id` of the cart item.
- **Live Response:** `405 Method Not Allowed` / `404 Not Found` (Client removes item from local storage).
- **Expected API Response:** `200 OK` / `204 No Content`.

### C. Checkout & Order Endpoints

#### 9. `POST /api/orders`
- **Method:** `POST`
- **Purpose:** Create new order from cart and shipping address.
- **Request Headers:** `Content-Type: application/json`
- **Request Payload:**
```json
{
  "shippingAddress": {
    "line1": "123 Broadway",
    "line2": "Suite 500",
    "city": "New York",
    "state": "NY",
    "postalCode": "10001",
    "country": "US",
    "phone": "2125550199"
  },
  "sameBillingAsShipping": true,
  "couponCode": "WINTER10"
}
```
- **Live Response:** `404 Not Found` (Client catches 404, synthesizes `local-<UUID>` order, saves to `localStorage["ecom-local-orders"]`, clears cart, and advances checkout).
- **Expected API Response:** `201 Created` with order object:
```json
{
  "id": "order_abc123",
  "orderNumber": "ORD-20261105-001",
  "status": "PENDING",
  "subtotal": "86.00",
  "discountAmount": "0.00",
  "shippingAmount": "0.00",
  "taxAmount": "6.88",
  "total": "92.88",
  "currency": "USD"
}
```

#### 10. `POST /api/payments/intents`
- **Method:** `POST`
- **Purpose:** Initialize payment intent for Stripe or payment gateway.
- **Request Payload:**
```json
{
  "orderId": "order_abc123"
}
```
- **Live Response:** Bypassed or returns 404 in offline fallback mode.

#### 11. `GET /api/orders/:id`
- **Method:** `GET`
- **Purpose:** Fetch single order details for order confirmation and account order detail views.
- **Path Parameter:** `id` (e.g. `local-c897a791-1b6f-4656-8cfc-82c80835be0c`).
- **Live Response:** `200 OK` (Loaded from `localStorage["ecom-local-orders"]`).

### D. Authentication Endpoints

#### 12. `POST /api/auth/login`
- **Method:** `POST`
- **Purpose:** User authentication.
- **Request Payload:**
```json
{
  "email": "customer@example.com",
  "password": "Password123!"
}
```
- **Live Response:** `404 Not Found` (Client falls back to local user store: email matching `"admin"` is granted `role: "ADMIN"`, other valid emails granted `role: "CUSTOMER"`).
- **Expected API Response:** `200 OK`:
```json
{
  "user": {
    "id": "usr_123",
    "name": "Demo User",
    "email": "customer@example.com",
    "role": "CUSTOMER"
  },
  "accessToken": "jwt_token_sample"
}
```

#### 13. `POST /api/auth/register`
- **Method:** `POST`
- **Purpose:** New customer registration.
- **Request Payload:**
```json
{
  "name": "Jane Doe",
  "email": "jane@example.com",
  "password": "Password123!"
}
```
- **Live Response:** `404 Not Found` (Client creates local user profile).

#### 14. `POST /api/auth/logout`
- **Method:** `POST`
- **Purpose:** Invalidate session token.
- **Live Response:** Client clears session state.

#### 15. `GET /api/csrf`
- **Method:** `GET`
- **Purpose:** CSRF token retrieval for form requests.
- **Live Response:** `200 OK` (Static HTML).

## 3. QA Automation Strategy for API Testing

Because Northline Store operates on a hybrid architecture (designed for real REST endpoints, but deployed on static Netlify with offline fallback), the test automation framework must support two distinct testing layers:

### Layer 1: Live Target Resilience & Fallback Tests
- Send actual requests to `https://ecomcicid.netlify.app`.
- Verify that frontend gracefully survives Netlify's 404/405 responses without uncaught runtime crashes.
- Verify `localStorage` state transitions (`ecom-cart`, `ecom-local-orders`, `ecom-auth`).

### Layer 2: API Contract & Mocked Endpoint Tests
- Use Playwright's `page.route("**/api/**", ...)` or `pytest` HTTP client with a mock server.
- Intercept `/api/products`, `/api/cart/*`, `/api/orders`, `/api/auth/*` and return standard `200`/`201` JSON payloads.
- Test both Happy Paths and Error Injections (e.g., `500 Internal Server Error`, `422 Unprocessable Entity`, `401 Unauthorized`) to verify UI error toasts, banners, and field-level validation indicators.
